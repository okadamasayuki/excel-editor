# Excel 抜粋エディタ

**https://okadamasayuki.github.io/excel-editor/**

Excel ブックを読み込み、プレビュー上で範囲を選び、ドラッグ＆ドロップまたは文章の指示で
出力シートに配置して、抜粋した Excel を書き出すブラウザツール。

処理はすべてブラウザ内で完結し、ファイルはどこにも送信されない。

## できること

| | |
|---|---|
| 読み込み | `.xlsx` / `.xlsm` / `.xlsb` / `.xls` / `.csv`。ウィンドウへのドロップ、またはファイル選択 |
| 複数ファイル | 元データは何個でも開ける。「元データ」の右にファイルが並び、クリックで切り替える（下のシートタブはそのファイルのぶんだけ）。左のシート一覧はファイルごとにまとまり、そこから選んでも切り替わる。別々のファイルから 1 枚の出力シートにまとめられる。× でそのファイルだけ閉じる（そのファイルを使っていたブロックも一緒に外れる） |
| 読み込み中の表示 | ファイル名・進み具合・段階（読み込み中 → 解析中）を表示。失敗時は理由を出す |
| プレビュー | Excel で開いたときに近い見え方。セルの塗りつぶし色、列ごとの幅、非表示の行・列を再現。大きなシートは仮想描画 |
| ウィンドウ枠の固定 | 行・列の見出しをクリック → メニューから固定。スクロールしても見出しと中身がぴったり重なったまま残る |
| 全画面表示 | 元データ・出力シートのどちらも画面いっぱいに広げて、Excel のように見る（Escで戻る） |
| 表示倍率 | 元データ・出力シートそれぞれに `− 100% ＋`。50%〜200% の 9 段階、数字を押すと 100% に戻る。倍率を変えても選択やドラッグの当たり判定はずれない |
| 画面の並べ方 | 元データと出力シートを左右／上下に切り替えられる。境目はドラッグで動かせる（ダブルクリックで半分に戻る）。左のブック構成は丸ごと畳めるほか、項目ごとにも畳める |
| 範囲選択 | セルのドラッグ、Shift+クリックで拡張、行/列見出しクリックで一括、左上の角クリック（または Ctrl+A）で全体、文章での指示 |
| 自動スクロール | 選択中に端まで引っ張ると、その方向へ送られて画面外の行・列が出てくる（Excel と同じ）。出力側もドラッグ中に送られる |
| 配置 | 選択した範囲は、どこを掴んでも出力シートへドラッグできる |
| 対応の見える化 | 出力へ持っていった範囲は、元データ側に色つきの枠として残る。枠の色は出力シートのブロックと同じなので、別のシートを見て戻ってきても・手順書で一気に置いても、どこがどこへ行ったかが色で分かる。出力側のブロックに触れると、元データ側の相手が光って行き先も出る |
| 末尾へ移動 | 「↓ 末尾の下へ移動」「→ 末尾の右へ移動」で、出力の続きが画面の真ん中に来るまで表示を動かす（置きはしない）。末尾は値の入っている範囲で判断し、**直接入力・フィルのセルも数える**（最後にさわった行が基準） |
| シートまるごと | シート一覧・シートタブをドラッグして出力シートへドロップ |
| 文章の指示 | 手順書に「売上明細のA1からE12を抜粋1のB2に置く」のように書く。1行でも複数行でも動く |
| 調整 | 置いたブロックはどこを掴んでもドラッグで置き直せる。行列の入れ替え（転置）は出力シートのツールバー、ほかに Ctrl+Z |
| まとめて外す | 出力シートで範囲を選んで **Delete**（または BackSpace）。その範囲に少しでも掛かるブロックが全部外れる。範囲を選んでいなければ、選択中のブロック 1 つ。どちらも Ctrl+Z で戻せる |
| 行・列の差し込み | 出力シートの行・列の見出しは **1回目のクリックで選択、もう一度クリックでメニュー**。そこから**上下・左右に空きを挿入**でき、先に始まるブロックや入力がずれる（またいでいるブロックはそのまま）。見出しの Shift+クリックで帯を広げれば、そのぶんまとめて挿入。Ctrl+Z で戻せる |
| 直接入力 | 出力シートの空きセルを**ダブルクリック**（F2 / そのまま文字を打っても）で、値・**数式**（`=SUM(A1:A5)` など）・日付を入力。Enter で下、Tab で右へ。ブロックの上には入力できない（元データとつながっているため）。Excel 生成・Python 書き出し・**手順書**（「…と書く」の行になる）ぜんぶに入る |
| フィル | 選択の**右下の■を引っぱる**と続きが入る（Excel のフィルと同じ）。日付は 1 日ずつ（2 個選ぶとその間隔）、数値は 2 個選ぶと等差、数式は参照をずらしてコピー、「第1回」の末尾の数字は増える。ブロックの値を種にもできる。**画面の端まで引くと自動でスクロール**し、足りなければ表そのものが伸びる。引いている間は**先端に入る値**が出る |
| 書式 | 直接入力したセルに、日付・数値・小数・パーセント・通貨・文字列の書式を選べる（出力ツールバーの「書式」）。Excel 生成・Python 書き出しにそのまま入る |
| 選択範囲の集計 | 出力シートで行・列やセル範囲を選ぶと、シートタブと同じ帯（Excel の下端と同じ位置）に個数・数値の個数・合計・平均・最大・最小が出る。ブロックをクリックすればその範囲ぶん（ブロックの上で選び直すときは Shift+ドラッグ。そのままのドラッグはブロックの移動） |
| 手順書 | 同じ作業を使い回す。行・列・シートの繰り返し、縦／横の並べ方、名前をつけた相対配置、ファイルでの受け渡し（下記） |
| 出力 | 複数の出力シート、数式の保持、結合セルの保持、列幅の引き継ぎ、`元ファイル名_抜粋.xlsx` で保存 |
| Python で書き出す | 今の配置を、そのまま動く Python 1 本にして書き出す。Snowflake のノートブックなどに貼れば、同じ抜き出しを続きの加工とひとつながりにできる。元ファイルの名前がぶれても読む（下記） |

## 手順書

毎月同じ抜き出しをする、半年後に別の人が同じ結果を再現する、といった用途のための機能。
右上の「手順書」ボタンで開く。**書けることは「書き方の一覧」ボタンで全部見られる**。
行にカーソルを合わせると、**そう書いたときにどこへ置かれるかが小さな表で動いて出る**。
行をクリックすればその書き方が手順書に貼り付く。手順書は手で書かなくてよい。
次の 3 ステップでできる。

1. **1 回ぶんだけ**ドラッグで並べる
2. **「今の配置から作る」** — 並べた結果がそのまま手順書の文章になる
3. **「繰り返しにする」** — **行・列・シート**のどれを繰り返すか選び、値を答える。
   その指示行が `繰り返し`〜`ここまで` で包まれ、共通する部分が `{行}` `{列}` `{シート}` に置き換わる

| 繰り返す対象 | 答え方 | 置き換わるもの |
|---|---|---|
| 行 | `10, 12, 17, 20`（`10-14` の範囲も可） | 指示行に共通する行番号 → `{行}` |
| 列 | `B, D, F`（`B-E` の範囲も可） | 指示行に共通する列名 → `{列}` |
| シート | `売上明細, 支店別サマリ`（開いているシート名が既定で入る） | 指示行に共通する元シート名 → `{シート}` |

（テキストエリアで行を選んでから「繰り返しにする」を押せば、その範囲だけを包める。
`シート追加` やコメント行は自動で繰り返しの外に残る）

```
# 元ファイル: 売上_2026.xlsx        ← # で始まる行はメモ。複数開いていれば全部並ぶ。開いていないと警告が出る
説明: 支店ごとの月次行を1枚にまとめる

シート追加 月次まとめ
売上明細のA2からE2を月次まとめのA1に置く（名前: 見出し）
支店別サマリのA1からC5を 見出し の下に1行あけて置く   ← 名前を目印に、その下へ

繰り返し 行 = 10, 12, 17, 20 / 横に並べる   ← 1周ぶんを右へ足していく（既定は縦に積む）
  売上明細の{行}行目を続けて置く            ← {行} が各値に置き換わる
  支店別サマリの{行}行目を続けて置く
ここまで
```

| 書き方 | 意味 |
|---|---|
| `シート追加 <名前>` | 出力シートを用意する。同名があれば使い回す（何度実行しても増えない） |
| `<シート>の<範囲>を<出力シート>の<セル>に置く` | 位置を指定して置く。範囲は `A1からD10` / `A1:D10` / `3行目` / `B列からD列` / `全体` |
| `…に置く（名前: <名前>）` | 置いたものに名前をつける。あとの行から位置の目印にできる |
| `…を <名前> の(右｜下｜右下)に置く` | 名前をつけたものの隣へ。**直前が何であっても**狙った相手のとなりに置ける |
| `…に <N>(行｜列)あけて置く` | すきまを空ける。`見出し の下に1行あけて置く` / `2列あけて続けて置く` |
| `[<ファイル名>]<シート>の…` | 別のファイルに同じ名前のシートがあるとき、どちらか決める。`[売上_2026.xlsx]売上明細のA1:C3を…` |
| `...を続けて置く` | 直前の続き（1つ下の行）に置く。列は行の左端に戻る |
| `...を右に続けて置く` | 直前の右隣に置く。横に並べたいとき |
| `...に置く（転置）` | 行と列を入れ替えて置く |
| `繰り返し <変数> = <値,...>` 〜 `ここまで` | 値の数だけ繰り返す。`{変数}` が各値に置き換わる。変数名が `列` のときは `B-E` を列の範囲として広げる |
| `繰り返し … / 横に並べる` | 1 周ぶんのかたまりを、周ごとに**右へ**足していく（既定は `縦に積む`）。`/ 1列あけて横に並べる` のようにすきまも指定できる |
| `<出力シート>の<セル>に「<内容>」と書く` | 出力シートのセルに直接書き込む。数式（`=SUM(A1:A5)`）や日付もそのまま。文字どおり読み直して同じ書式に戻らないときだけ `（書式: 0.0%）` が付く |
| `生成` | そこまでの結果を xlsx として書き出す。手順書の最後に置いておける |

繰り返しの中でセル位置を明示した行も、2周目以降は前の周のぶんだけずれる（`縦に積む` なら下へ、
`横に並べる` なら右へ）。毎回同じ場所に重ならないようにするため。

「続けて置く」は**その周で置いたものの下**に続ける。離れた場所に背の高いものがあっても
引っぱられない。「◯◯ の右に置く」で名前を指したときは、直前が何であってもその相手のとなりへ置く。

手順書は**テキストファイルとして書き出して他の人に渡せる**。渡された側はファイルから読み込んで
実行するだけで同じ結果になる。ブラウザには保存しない。

## Python で書き出す

手順書の「Python を書き出す」から、**いまの配置と同じことをする Python** を 1 ファイルで
書き出せる。指定するのは**書き出す Excel の名前**と**シート名**だけ。元ファイルは、書き出した
Python と同じ場所（Snowflake ならノートブックと同じ階層）に置いておけばよい。

```python
SOURCES = ["売上_2026.xlsx"]           # 読み込む元ファイル
OUTPUT  = "売上_2026_抜粋.xlsx"
SHEETS  = {"まとめ": "月次まとめ"}      # 左が画面のシート名、右が書き出す名前
SEARCH_DIRS = ["."]                    # 探す場所。既定は「今いるところ」

PLAN = [   # 画面の配置がそのまま並ぶ
    {"out": "まとめ", "file": "売上_2026.xlsx", "sheet": "売上明細",
     "src": "A1:E8", "at": "A1", "transpose": False},
    ...
]

EDITS = [  # 画面で直接入力したセル（値・数式・日付・書式）もそのまま入る
    {"out": "まとめ", "at": "A15", "kind": "d", "value": "2026-08-01", "format": "yyyy/m/d"},
    {"out": "まとめ", "at": "B15", "kind": "f", "value": "=SUM(B2:B8)", "format": None},
]

build()                       # OUTPUT に書き出して、実際に書けた場所を返す
data   = build_bytes()        # ファイルを作らず、xlsx の中身を bytes で受け取る
frames = to_dataframes()      # 続きの加工をするなら {シート名: DataFrame}
```

必要なのは **openpyxl だけ**（`to_dataframes()` を使うときだけ pandas を読み込む）。
数式の保持・結合セルの保持・行列の入れ替え・列幅の引き継ぎは画面の設定がそのまま入る。
手順書の文章は貼り付けない（`PLAN` が実行結果そのもの）ので、手順書が何百行あっても
書き出す Python の前書きは変わらない。

**元ファイルの名前はぶれてよい。** `08.03更新_2026年度費別管理表.xlsx` が
`02.17更新_2026年度費別管理表.xlsx` や `2026年度費別管理表(01.23更新).xlsx` になっていても読む。
日付・連番の値と位置、全角と半角、`（最新版）` のような飾り、区切り記号のちがいは吸収して、
いちばん近いものを選ぶ（読んだ名前は実行時に表示する）。

近さが同じときは **①年度など数字のそろうほう → ②更新の新しいほう** の順に決めるので、
`2025年度` と `2026年度` が同じフォルダにあっても、年度のそろうほうを選ぶ（そちらが古くても）。
どれも似ていなければ、その場にある Excel を並べて理由を知らせる（`部門別管理表` を
`費別管理表` として読んでしまうことはない）。

**seek（位置の移動）を使わない。** Snowflake のワークスペースのようにネットワークへ
マウントされたファイルシステムは seek ができず、`openpyxl.load_workbook(パス)` や
`Workbook.save(パス)` がそのまま失敗する（`Operation not supported`）。書き出す Python は
`os.open` / `os.read` / `os.write` でファイルを**頭から一気に**読み書きし、位置の移動が要る
zip の組み立て・取り出しはメモリの上だけで行う。ファイルに対して `seek` も `tell` も呼ばず、
組み込みの `open()` も使わない（テストで毎回確認している）。

**書き込めない場所でも止まらない。** それでも保存できないフォルダだったときは、作業用
フォルダへ逃がしてその場所を返す。貼り付けたセルがそのまま走る環境でも例外を投げず、
うまくいかない理由だけを出す。ファイルを一切作りたくなければ `build_bytes()` や
`to_dataframes()` を使う。

前段の Excel 加工を画面で、後段の加工を Snowflake の Python で、と分かれていたものを
1 本のノートブックにまとめられる。テストでは、書き出した Python を実際に走らせて、
**画面が書き出す xlsx と 1 セルも食い違わないこと**、シート名を変えても中身が同じこと、
名前をぶらした元ファイルでも同じ結果になること、書けない場所を指しても書き出せることを
毎回確認している。

## 扱うファイルについて

読み込んだ Excel はブラウザの外に出ない。SheetJS を含む全てのコードを 1 ファイルに埋め込んで
あり、ページを開いたあとは**外部への通信が一切発生しない**。テストでは実際にブラウザの全通信を
記録し、ページ本体の取得以外が 0 件であることを毎回確認している（`test/e2e.mjs`）。
読み込んだブックは何個開いてもタブのメモリ上にあるだけで、手順書も含めどこにも保存されない
（再読み込みで消える）。
ブラウザに残るのは画面の好み（並べ方・折りたたみ・境目の位置・表示倍率）だけで、
シート名もセルの値も含まない。これらもテストで確認している。

なお、公開しているリポジトリと Pages は誰でも見られるので、**会社のデータそのものをコミットしない**こと。

## 構成

```
src/index.html    アプリ本体（HTML + CSS + JS）
vendor/           SheetJS 0.18.5（Apache-2.0）
build.mjs         SheetJS を埋め込んで配布物を作る
docs/index.html   GitHub Pages で公開される単一ファイル（完全な HTML 文書）
dist/index.html   Artifact 用の断片。<html>/<head>/<body> は配信側が付ける
test/e2e.mjs      Playwright による通し検証（選択 → 配置 → 生成 → 中身の照合）
test/fixtures/    色・非表示・列幅つきの検証用ブック（openpyxl で作成）
```

どちらの成果物も外部へのリクエストを一切しない（SheetJS を含め全て埋め込み済み）。

## 公開

`.github/workflows/pages.yml` が push のたびに `docs/` を GitHub Pages へ配信する。
ワークフローは `docs/` をビルドし直し、コミット済みの内容と一致するかを確認するので、
`src/` を変更したら `node build.mjs` の結果を一緒にコミットすること。

## 開発

```sh
node build.mjs     # docs/index.html と dist/index.html を生成
node test/e2e.mjs  # ブラウザで通しテスト（403項目）＋ スクリーンショット
```

テストは生成された `.xlsx` を SheetJS で読み直し、値・型・配置先セルまで照合する。
書き出した Python も `python3` で実際に走らせ、画面の書き出しと突き合わせる
（`python3` か `openpyxl` が無い環境では、その照合だけを飛ばす）。
「書き方の一覧」に載せた書き方は、実際に実行してエラーが出ないことも毎回確認している
（説明と実装が食い違わないように）。

### 注意

Chromium はロケールに従ってダウンロード名を正規化するため、`C` ロケールのままだと日本語の
ファイル名が `download` に落ちる。テストは `LANG=C.utf8` を与えて実機と同じ条件で起動している。

`XLSX.read` は同期処理でメインスレッドを止めるため、「解析中」の表示は必ず 1 回描画させてから
解析に入る（`afterPaint`）。そうしないと表示が変わらないまま固まったように見える。この間は
ページ側の JS もスクリーンショットも応答しないので、表示の検証は MutationObserver で
段階の遷移を記録して行っている。

`overflow-x: auto` だけを指定すると、もう一方の軸は `visible` のままにならず `auto` に
なる（CSS の仕様）。シートのタブは高さがぴったりなので、下線が 1px はみ出しただけで
上下のスクロールバーが出てしまう。`overflow-y: hidden` を明示し、下線も枠の内側に置いている。

`XLSX.read` は中身の無いファイルでも例外を出さず 1 セルのブックを返す（プレーンテキストや
空ファイル）。そのまま通すと、開いていたブックが空の表に差し替わって失われるため、
セルが 1 つも無いブックは読み込まずに警告する。

### SheetJS から取れる書式・取れない書式

`cellStyles: true` で取れるもの／取れないものを実ファイル（`test/fixtures/書式つき.xlsx`）で
確認した結果は次のとおり。取れないものは再現していない。

| | |
|---|---|
| セルの塗りつぶし `s.patternType` / `s.fgColor.rgb` | 取れる |
| 列の非表示・幅 `!cols[].hidden` / `.wpx` | 取れる |
| 行の非表示 `!rows[].hidden` | 取れる |
| 結合セル `!merges` | 取れる |
| フォント色・太字 | **取れない**（Community 版の制限） |
| ファイル側のウィンドウ枠の固定 `!freeze` | **取れない** → 画面から手動で固定する |

表示倍率は CSS の `zoom` をグリッド全体に掛けて実現している。中の座標系は変わらないので
描画・配置・固定はそのまま動く。画面上の位置から中の座標に戻すところ（クリック・ドラッグの
当たり判定と、端の自動スクロール）だけ倍率で割る。

グリッドは列ごとに幅を持つ累積座標で位置を決めており、非表示は「幅 0」として同じ仕組みで
扱う。見出しと固定した行・列は、大きさ 0 の `position: sticky` の入れ物に入れて貼り付ける
（縦だけ／横だけ／縦横とも、の 3 種類）。位置決めをブラウザに任せるのが要点で、JS で
スクロール量ぶんずらすやり方だと、1 フレーム遅れて追いかけたり小数のスクロール量と
わずかに食い違ったりして、固定した部分が細かく震えて見える。入れ物は大きさ 0 なので
中の層の座標（見出し幅を含んだ絶対座標）はそのまま使える。

全画面表示は「上下に並べる」「ブック構成をたたむ」より後に、クラスを重ねた強さで書く。
先に書くと後続の並べ方の指定に負け、1 枚になった画面が 34px の列や元の高さのままの行に
押し込まれてしまう。

スクロール位置そのものにも手を出さない。Excel のように行・列の区切りへ吸い付かせると、
ブラウザ自身のスクロール（なめらかスクロールや慣性）と引っぱり合って画面が震える。
区切りに合わせていたころは、4px 動かしただけで 1 列ぶん先へ飛ばされていた。
境目で列が途中で切れることは受け入れて、見出しと中身が必ず一致することを優先している。
